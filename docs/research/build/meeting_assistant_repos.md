# Open-source real-time meeting / desktop AI assistant repos reusable for Tap (LauzHack 2026)

Observation date: 2026-11-21. Star counts, licences and last-push dates come from the GitHub REST API (`api.github.com/repos/<owner>/<repo>`) that day. Source files were read from raw.githubusercontent.com (HEAD).

## 1. cheating-daddy (sohzm/cheating-daddy): architecture, capture, STT, overlay, licence, reusable files

### Takeaway
cheating-daddy is a small, readable plain-JS Electron 30 app. It uses no bundler, and Lit is vendored as a static file. It captures Windows system audio with `getDisplayMedia` plus `desktopCapturer` with `audio: 'loopback'`. It resamples to 24 kHz mono 16-bit PCM in 100 ms chunks through a ScriptProcessor and streams that to the Gemini Live API (`gemini-3.1-flash-live-preview`), with input transcription and speaker diarization turned on. A local whisper.cpp option also exists. The licence is GPL-3.0. Three pieces are worth reusing as patterns or copied code: the Windows loopback capture path, the PCM chunking, and the Gemini Live session config. The content protection, taskbar hiding, "emergency erase" and the interview "answer" prompts should not be reused.

### Inferences
- **Reusable for Tap**. Re-implement these as patterns; copy only if you accept GPL:
  1. The `setDisplayMediaRequestHandler` + `audio: 'loopback'` block (about 8 lines) and the renderer `getDisplayMedia` call. This is the simplest working way to capture Windows system audio in Electron without native modules. It is a few lines of standard Electron API, so rewriting it from the Electron docs is trivial and avoids GPL contamination.
  2. The Float32→Int16→base64 chunking at a fixed rate. For Tap, use 16 kHz if the STT is Deepgram, Whisper or AssemblyAI. Use 16 kHz input as well for current Gemini Live, which accepts 16 kHz PCM. The 24 kHz here is a cheating-daddy choice. Swap the deprecated ScriptProcessor for an AudioWorklet if you have time.
  3. The Gemini Live config pattern (`inputAudioTranscription` + diarization + `sendRealtimeInput`) if Tap uses Gemini Live for transcription. Set `responseModalities` to TEXT or keep the transcription only. Disable `proactiveAudio`.
  4. Overlay basics: frameless, transparent, `setAlwaysOnTop(true,'screen-saver')`, and `setIgnoreMouseEvents(true,{forward:true})` for a recap card that does not steal clicks.
- **Do not reuse**: `setContentProtection(true)`, `setSkipTaskbar(true)`, `setHiddenInMissionControl`, emergency erase, the interview/"answer for me" prompts in `prompts.js`, and the paid cloud endpoint. Tap should be visible on screen share and in the taskbar, and should show a clear "listening" indicator. That fits its accessibility framing (cues for non-speaking, hard-of-hearing or distracted users) and the consent norms around recording other participants.
- Gemini Live is not "on-device". If the PRD promises on-device processing, keep Gemini Live only as an optional cloud path, or follow cheating-daddy's local whisper.cpp approach.
- Security debt: `nodeIntegration: true` with `contextIsolation: false`. Do not copy this into a demo that loads remote content.

### Gaps
- I did not verify that this code works on current Windows 11 builds. The open issues #161 and #168 suggest it is fragile, and the Electron 30 loopback behaviour differs across versions (see electron-audio-loopback below).
- I did not read `prompts.js` or `CheatingDaddyApp.js` in full.

### Inferences
- Most Electron clones (cheating-daddy, Glass, cue) inherit the same Windows approach: getDisplayMedia + `audio:'loopback'`. Rust/Tauri apps (Pluely, Meetily, anarlog) use WASAPI loopback directly through the `wasapi` crate or `cpal`'s WASAPI host. Rust is more robust, but a TypeScript/Python team cannot easily absorb it in 24 hours.
- RealtimeSTT's wake-word and VAD design fits the "name said" trigger well. You can also run faster-whisper or Deepgram and do keyword matching on partial transcripts. Deepgram's keyword boosting helps with an unusual user name. That is an inference; I did not verify it against Deepgram docs here.
- Glass's WASM AEC idea (subtracting system audio from the mic) matters only if Tap transcribes the user's mic and the user is not wearing headphones. Tap mostly needs the other participants' audio, which is the loopback stream, so AEC is optional.

## 3. Best base/reference for Tap (24 h, Windows, TS/Python) and licence implications

### Takeaway
Do not fork any of these apps. Start a fresh Electron + TypeScript app, or Electron UI plus a Python sidecar. Use the MIT `electron-audio-loopback`, or re-implement the 10-line `setDisplayMediaRequestHandler({audio:'loopback'})` pattern from Electron docs, for system audio. Use `getUserMedia` for mic and webcam (face gestures via MediaPipe in the renderer). Stream 16 kHz PCM to one STT: Deepgram or Gemini Live for speed, or a Python faster-whisper/RealtimeSTT sidecar for on-device processing. Use cheating-daddy (GPL) and Pluely (GPL) as read-only references, and Meetily/anarlog (MIT) as copyable references if anyone touches Rust. Declare every reference under LauzHack Rule 30.

### Inferences
- **Licence implications**: copying GPL-3.0 files such as `renderer.js` or `window.js` into Tap's repo means the combined work must be distributed under GPL-3.0 if distributed at all. That is acceptable for a public hackathon repo if the team chooses GPL, but it blocks a later proprietary or permissive pivot. Reading GPL code and re-implementing standard Electron API calls (`setDisplayMediaRequestHandler`, `getDisplayMedia`, `AudioContext`, `setAlwaysOnTop`, `setIgnoreMouseEvents`) from Electron docs is low-risk. Either way, declare it under LauzHack Rule 30 (for example: "Audio loopback pattern inspired by sohzm/cheating-daddy (GPL-3.0); electron-audio-loopback (MIT) used as dependency").
- **Recommended 24 h split (team of 4)**:
  1. Electron shell with a transparent, always-on-top, click-through recap card that stays visible and is not content-protected. Pattern from cheating-daddy `window.js`, minus the stealth lines.
  2. Audio: `electron-audio-loopback` or the `audio:'loopback'` handler, plus an AudioWorklet that downsamples to 16 kHz Int16. Alternatively, a Python sidecar with PyAudioWPatch WASAPI loopback, then faster-whisper/RealtimeSTT, sending transcripts to Electron over WebSocket.
  3. Trigger engine: name/keyword match and a question heuristic ("?", "can you hear me", the user's name followed by a question within N seconds) on streaming partials. This drives Logitech haptics and the card.
  4. Webcam face gestures via MediaPipe, plus the Logitech SDK.
- **Speed vs on-device**: Gemini Live or Deepgram streaming gives the fastest, most accurate partials with the least code (cheating-daddy's `gemini.js` shows the config). A local faster-whisper sidecar honours "on-device" but adds latency (about 1–2 s chunks) and Windows setup risk. Meetily's README notes the AVX2 and Vulkan requirements. A pragmatic plan is a cloud STT for the demo and a local Whisper fallback flag.
- **Ethical framing for the PRD**: Tap reuses only the capture and overlay mechanics. It explicitly rejects the content protection, hidden taskbar entry, emergency erase and "answer for you" features that define cheating-daddy, Pluely and OpenCluely. It is a visible accessibility and attention aid, and participants should be told transcription is happening.
